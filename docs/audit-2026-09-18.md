# Security and consolidation audit

Initial review: 18 September 2026. Product follow-up: 19 September 2026.
Working branch: `audit/consolidation-security`. This is a source review and local
validation report, not a security certification or native penetration test.

## Updated conclusion

Notes/folders have working local persistence and useful shared UI. Task and Project
are prototype models, not complete persistent task/Kanban workflows. Collaboration
is a target, not an existing protocol. The most important remaining work is native
lock/privacy validation, recovery UX, transactional commands and orphan handling.

The original migration blocker is **superseded**: the owner confirmed that the app
has never shipped and all existing data is disposable test data. Plaintext database
recovery and JSON migration have therefore been removed. Known plaintext backups
are deleted rather than preserved. Do not apply this policy to released user data.

Product clarifications are recorded in [product rules](product-rules.md), including
search scope, inherited folder authentication, clear/encrypted exports, import lock
fallback, allowed diagnostic fields and Premium boundaries.

## Scope and evidence

Reviewed models, repositories, crypto wrappers, import/export, note access,
preferences, startup, diagnostics, Android/iOS configuration, CI, shared UI,
documentation and tracked publisher information. Added regression tests, ran static
analysis and local widget/golden suites. No real-device integration, native build,
Sentry console audit or store submission was performed in the initial review.

Initial pattern scan: 314 tracked files, searching private keys, GitHub tokens,
AWS keys and Sentry auth tokens; no matching secrets found. This is not exhaustive
and does not establish absence of secrets in old commits. OSV querybatch checked
122 hosted Pub packages in `pubspec.lock` and returned no advisories at the time.
Native transitive dependencies and unknown vulnerabilities were not covered.

Import validates before writes. Production SQLite implements `AtomicNoteImporter`;
alternative production adapters must provide equivalent atomic behavior. Files and
SQLite are not one transaction: interruption may leave encrypted orphan files.

## Functional interpretation

A locked folder is an authenticated scope; a child retains its own lock flag when
moved. A link from an unprotected note to a protected destination prompts. An
unrelated authenticated note is not blanket authorization. All individually locked
objects are excluded from search. Home includes eligible folder contents; folder
search is strictly scoped. An unlocked child inside an already-open locked folder
can appear in that folder's search, but not global search.

Clear export decodes local encryption and clears object locks. Encrypted export
preserves locks. Import preserves them when the device can authenticate, otherwise
unlocks imported objects and reports the count. Current v1 only carries notes/files;
these rules must extend to future object types when their format is implemented.

## Remaining release risks

### Native lifecycle and locks

Revalidate authorization after backgrounding and protect app-switcher snapshots.
Test navigation, links, trash, export, process death and removed OS credentials on
actual devices. Local policy does not substitute for future peer authorization.
Keys and decoded content remain in process memory during use.

### Diagnostics

Validate final envelopes after native enrichment, offline queues, consent revocation
and restart. `Sentry.close()` may flush queued reports. Native crash reporting remains
disabled until equivalent filtering is proven. Without a configured DSN there is no
Sentry initialization. Verify service-side IP non-retention, retention period and
access controls before release. Locale country is a configured region, not location.
Allowlisted model/OS fields are technical data but combining rare attributes can
still increase identifiability; keep the list small.

### Recovery and persistence errors

Keystore failure correctly fails closed but needs a recovery screen. Some UI paths
still expose unnormalized I/O/write failures or update visible state before a write
succeeds. Shared commands should authorize, validate, persist, then notify. Test disk
full, interruption and retry without destructive resets.

### Files and reset

Encrypted attachment orphans can remain after deleting notes or interrupted import.
Build reference-aware cleanup across active and trash entities, plus recovery.
External-viewer temporary files should expire with a safe lifecycle policy; copies
made by other applications cannot be recalled. Reset is not one transaction over
all preferences, records and files. Known legacy plaintext backups are now removed.

### Formats, scale and supply chain

V1 is not a complete app backup. Add v2 with folders, relations, versioned validation
and round-trip tests. Measure large-data search/pagination and expensive crypto/ZIP
work; add fuzzing and memory profiling. Pin verified CI action revisions and Flutter
versions for reproducibility. Check native packages separately from Pub advisories.
Before first publication, establish non-destructive future migrations and recovery.

## Factorization and future implementation

Keep typed business models. Shared read contracts, sorting and nullable semantics
remove simple duplication; next extract domain commands, not a universal mutable
JSON entity. Tasks need status/deadline rules, projects need columns and stable order,
and both need persistence/migrations before production screens.

Premium's current foundation defines projects/sharing/collaboration as paid features,
with a free production entitlement and an honest information page. No payment/store
adapter exists until the model is decided. A verified entitlement will be separate
from authorization to shared data.

Remote collaboration requires authenticated invitations, per-space keys, operation
IDs, causal dependencies, permissions, replay protection and a conflict strategy.
A relay may be needed for remote NAT traversal; it must not retain content.
See [collaboration](collaboration.md). No fake networking layer was added.

## Publisher information and git identities

Author name, public policy contact, GitHub URLs and bundle ID are public publisher
information and remain intentional. The old license email, shared Apple team and
Sentry account defaults were removed. Changing the bundle ID can break distribution.
Build identity/signing files remain outside version control; compiled defines are
not secret storage. Documentation is public even when not deployed to Pages.

The follow-up authorizes normalizing historical author/committer identities to the
current address, preserving GitHub's genuine merge committer. Git author identity
cleanup does not remove old strings from historic file contents, fork copies or
GitHub caches. A local recovery backup is needed while rewriting refs; it is not
published. Verified GitHub state on 19 September: four remote branch histories updated
(master, polish/global, quality/tests-and-logs, ux/public-polish), with unchanged
commit trees and lease-protected atomic push. Develop was fast-forwarded to master
and made default. Master now requires a PR, one independent approval and successful
Analyze & test / Build (apk) / Build (ios) checks. Admins are included; force pushes
and deletion are disabled. Old identities are absent from reachable local commits
and reflogs. The existing stash and staged/unstaged work were preserved. A private
recovery bundle remains under the temporary directory; no audit code was committed
or pushed by this operation.

## Verification history

Baseline: 280 tests excluding goldens, clean analysis. The initial consolidation
passed 316 tests including 20 local goldens; five regression cases had first failed
against the previous code. No golden reference images were regenerated.

The follow-up changes product expectations and adds tests for disposable legacy
data, disabled lock controls, scoped links/search, technical diagnostic fields and
Premium access boundaries. See [tests](tests.md) for commands and validation limits.
Follow-up result: **320 tests pass**, including 20 goldens; analysis reports no
issues. Documentation links and diff whitespace checks pass. Golden reference images
were not changed. A successful Flutter suite does not prove native encryption or
service-side privacy. CI triggered by history updates is separate from these local
checks; it runs the existing remote code, not the uncommitted audit changes.
